
# Structure of the OS Source Code

Now that you have built the OS, you might want to change or append to some of the customizations made in the meta-l1calo layer. The following is a guide through the different files and folders of the project, and what they affect in the final OS image.

## Top-Level Structure: `xilinx_bitbake`

When you first use the `setup.sh` script, it will generate the top-level folder for the project, named `xilinx_bitbake`. After building, it should be organized as such:

```
xilinx_bitbake
└── build
│   └── ...
└── sources
|   └── ...
└── tmp_sdt
|   └── ...
└── output
|   └── ...
└── setupsdk
└── repo
└── generate_device_tree.sh
└── copy_output.sh
└── write_output_to_sd.sh
```

You have four folders: `build`, `sources`, `tmp_sdt`, and `output`. You also have a few shell scripts. Here are their summary:

| Name | Type | Created by | Purpose |  
| :--- | :-- | :-- | :-- 
| `build` | *folder* | [setup.sh](../scripts/setup.sh) line 16 | Used by the `bitbake` command when building the final OS image. |
| `sources` | *folder* | [setup.sh](../scripts/setup.sh) line 13 | Contains all of the layers used by yocto for the OS image |
| `tmp_sdt` | *folder* | [generate_device_tree.sh](../scripts/generate_device_tree.sh) line 6 | Contains all of the device tree components generated from the board's XSA layout file, which eventually end up in the final PetaLinux device trees |
| `output` | *folder* | [copy_output.sh](../scripts/copy_output.sh) line 2 | Contains a copy final OS image output after `bitbake` finishes creating it in the `build` folder|
| `setupsdk` | shell script | [setup.sh](../scripts/setup.sh) line 10 | Setups up the yocto `bitbake` environment for the current shell. If the shell is exited or a new shell is entered, `source setupsdk` must be run again |
| `repo` | shell script | [setup.sh](../scripts/setup.sh) line 6 | Used by the initial part of `setup.sh` to download and run the list of all of the yocto layers included by Xilinx |
| `generate_device_tree.sh` | shell script | [setup.sh](../scripts/setup.sh) line 24| Run after the initial setup to generate both the contents of `tmp_sdt` (the intermediate device tree files based on the gFEX board XSA layout file), and the final OS device trees in `sources/meta-l1calo/conf/dts/<MACHINE>` |
| `copy_output.sh` | shell script | [setup.sh](../scripts/setup.sh) line 25 | Run after `bitbake` finishes creating the OS Image to copy the relevant OS Image files to `output` |
| `write_output_to_sd.sh` | shell script | [setup.sh](../scripts/setup.sh) line 26 | Run after `copy_output.sh` to write the OS Image in the .wic file inside the `output` folder to the appropriate SD card |

│   └── recipes-bsp
│   │   └── ...
│   └── recipes-gfex
│   │   └── ...
│   └── recipes-python

The relevant folders for modification are the ones in `meta-l1calo`; they are described in the following subsections:

### Subfolder 1: `meta-l1calo/conf`

This is the `conf` (i.e. configuration) folder for the machine/platform of the OS:
```
conf
└── dts
│   └── <MACHINE>
│   │   └── <MACHINE>-cortexa53-fsbl.dts
│   │   └── <MACHINE>-microblaze-pmu.dts
│   │   └── cortexa53-linux.dts
│   └── zynqmp-generic-sdt-full
│   │   └── ...
└── machine
│   └── include
│   │   └── <MACHINE>
│   │   │   └── <MACHINE>-cortexa53-fsbl-features.conf
│   │   │   └── <MACHINE>-cortexa53-fsbl-libxil.conf
│   │   │   └── <MACHINE>-microblaze-pmu-features.conf
│   │   │   └── <MACHINE>-microblaze-pmu-libxil.conf
│   │   │   └── microblaze.inc
|	└── gfex-production.dtsi
|	└── <MACHINE>.conf
└── multiconfig
│   └── <MACHINE>-cortexa53-fsbl.conf
│   └── <MACHINE>-microblaze-pmu.conf
```
All of the folders/files that have `<MACHINE>` in their name (this is the name chosen for the board, such as `gfex-production-stf`), are generated by the `gen-machineconf` command in `generate_device_tree.sh`.

The `dts`, or Device Tree Source folder, has the final device trees generated when running `generate_device_tree.sh`. They are the device trees used by the **First Stage Boot Loader** (FSBL), the **Platform Management Unit** (PMU), and the Linux kernel: these are `<MACHINE>-cortexa53-fsbl.dts`,  `<MACHINE>-microblaze-pmu.dts`, and `cortexa53-linux.dts`, respectively.

Importantly, the `machine` folder includes `gfex-production.dtsi`, the manually-written device tree file that includes custom device tree nodes for gfex boards.

The `machine` and `multiconfig` folders also includes the configuration files that are generated by `gen-machineconf`.

### Subfolder 2: `meta-l1calo/recipes-core`
This is the `recipes-core` folder, containing **core recipes** (build instructions for essential system components):
```
recipes-core
└── images
│   └── core-image-gfex.bb
└── init
│   └── init-<gfex-init script>
│   │   └── init-<gfex-init script>.service
│   │   └── init-<gfex-init script>.[sh/py]
│   └── init-<gfex-init script>_X.0.0.bb
│   └── ...
└── base-files
│   └── base-files_%.bbappend
└── root
│   └── ...
```
The most important file in this folder is `images/core-image-gfex.bb`, since it contains all the major recipes/components that `bitbake` must include in the final OS image.

The `init` folder contains all of the scripts that PetaLinux needs to run at boot, before the user can login (these are marked `[gfex-init]` when booting).

The `base-files` folder and `.bbappend` file load the custom folders of the gFEX OS into the filesystem image.

The `root` folder installs the [XRootD library](https://xrootd.org) to the OS.

### Subfolder 3: `meta-l1calo/recipes-kernel`
This is the `recipes-kernel` folder, containing relevant configuration for the OS's **kernel** (the core of an operating system, managing system resources like memory, CPU, and IO devices):
```
recipes-kernel
└── linux
│   └── files
│   │   └── add-trace-for-gator.cfg
│   │   └── disable-cpu-idle.cfg
│   └── linux-xlnx_%.bbappend
└── gator
│   └── files
│   │   └── ...
│   └── gator
│   │   └── gator.init
│   └── gator_git.bb
```
This folder has two subfolders: the `linux` subfolder adds `.cfg` files with different custom Linux kernel configurations ("Kconfigs"). The `gator` subfolder adds a "Target-side program gathering data for ARM Streamline Performance Analyzer".

### Subfolder 4: `meta-l1calo/recipes-support`
This is the `recipes-support` folder, containing supporting tools and libraries:
```
recipes-support
└── chrony
│   └── files
│   │   └── chrony.conf
│   └── chrony_%.bbappend
```
Right now, it has configurations for the [chrony library](https://chrony-project.org) implementing the Network Time Protocol (NTP) to synchronise the system clock with NTP servers.

### Subfolder 5: `meta-l1calo/recipes-bsp`
This is the `recipes-bsp` folder, containing the Board Support Package (BSP) layer configuration (recipes specifically related to the hardware platform targets):
```
recipes-bsp
└── external-hdf
│   └── files
│   │   └── zfpga_top.xsa
│   │   └── zfpga_top_golden.xsa
│   │   └── gfex-zynqmp.xsa
│   │   └── gfex-DMA.xsa
│   └── external-hdf.bbappend
```
It stores the Xilinx Support Archive (XSA) files generated by Xilinx Vivado, detailing the layout of the gFEX board. The only one used in the upgraded workflow is `zfpga_top.xsa`, in `generate_device_tree.sh`.

### Subfolder 6: `meta-l1calo/recipes-gfex`
This is the `recipes-gfex` folder, containing the gFEX repositories from CERN's gitlab:
```
recipes-gfex
└── gfex-management-scripts_git.bb
└── gfex-opcua-server-milkyway_git.bb
└── gfex-register-access_git.bb
```
The folder includes three repositories that all end up in `/software` in the final OS:
- [gfex-management-scripts](https://gitlab.cern.ch/atlas-l1calo/gfex/gfex-management-scripts) are a set of scripts used in the setup and testing of gFEX boards
- [gfex-opcua-server-milkyway](https://gitlab.cern.ch/atlas-l1calo/gfex/opc-ua-gfex-milkyway-server) are a set of scripts used for an OPC UA server
- [gfex-register-access](https://gitlab.cern.ch/atlas-l1calo/gfex/gfex-register-access) are a set of Python scripts to access registers and the playback memory on the gFEX board

### Subfolder 7: `meta-l1calo/recipes-python`
This is the `recipes-python` folder, containing the necessary python modules needed for custom scripts in the OS:
```
recipes-python
└── python3-bigtree_0.9.4.bb
└── python3-milkyway_git.bb
└── python3-construct_2.10.67.bb
└── python3-opcua_0.98.13.bb
└── python3-humanreadable_0.3.0.bb
└── python3-schedule_1.1.0.bb
└── python3-ironman_0.6.0.bb
```
These files include the specific version, and the dependencies of, each python module the OS requires.

### Subfolder 8: `meta-l1calo/wic`
The `wic` folder contains one file:
```
wic
└── gfex-sdimage.wks
```
This file has the SD card partition setup for making the `.wic` OS image.

### Subfolder 9: `meta-l1calo/docs`
This folder! It contains the documentation for this repo.

### Subfolder 10: `meta-l1calo/scripts`
The `scripts` folder contains shell scripts that automate the building, formatting, and writing process:

```
scripts
└── setup.sh
└── sdt.tcl
└── generate_device_tree.sh
└── copy_output.sh
└── format_sd_card.sh
└── format_sd_card_macOS.sh
└── write_output_to_sd_manually.sh
└── write_output_to_sd.sh
```

The three scripts for setting up the `bitbake` environment are `setup.sh` (downloads the necessary yocto layers and sets up bitbake), `sdt.tcl` (TCL scripts run by Vitis's `xsct` to generate device tree source files from `zfpga_top.xsa` and `gfex-production.dtsi`), and `generate_device_tree.sh` (which runs both the tcl script and `gen-machineconf` to generate the final device trees).

The `copy_output.sh` script copies the final OS image in the `xilinx_bitbake/build` folder to the `xilinx_bitbake/output` folder for easy locating.

Then, for formatting and writing to an SD card, there are two options. You can manually format and copy the correct files to the SD card using `format_sd_card.sh`/`format_sd_card_macOS.sh` and `write_output_to_sd_manually.sh`, or you can just write the `.wic` file directly (which handles formatting and the correct file placement) with `write_output_to_sd.sh`.

## Folder 2: `tmp_sdt`

Now we look at the structure of the `xilinx_bitbake/tmp_sdt` folder, which gathers all of the intermediary device tree sources. It is completely created by `generate_device_tree.sh`:

```
tmp_sdt
└── sdt.tcl
└── std_outdir
│   └── include
│   │   └── ...
│   └── system-top.dts
│   └── zynqmp.dtsi
│   └── zynqmp-clk-ccf.dtsi
│   └── pl.dtsi
│   └── pcw.dtsi
│   └── gfex-production.dtsi
│   └── ...
```

The most important output files is `system-top.dts`, since it is used by `gen-machineconf` to create the final device trees in `meta-l1calo/conf/dts/<MACHINE>`. `system-top.dts` includes all the `.dtsi` files shown in the directory illustration above.

## Folder 3: `build`

Now we look at the relevant structure of the `xilinx_bitbake/build` folder after `bitbake core-image-gfex` has been run:

```
build
└── conf
│   └── local.conf
│   └── ...
└── cache
│   └── ...
└── output
│   └── ...
└── tmp
│   └── deploy
│   │   └── images
│   │   │   └── <MACHINE>
│   │   │   │   └── boot.bin
│   │   │   │   └── boot.scr
│   │   │   │   └── Image
│   │   │   │   └── system.dtb
│   │   │   │   └── u-boot.bin
│   │   │   │   └── core-image-gfex-<MACHINE>.rootfs.ext4
│   │   │   │   └── core-image-gfex-<MACHINE>.rootfs.wic
│   │   │   │   └── ...
│   │   └── ...
│   └── ...
└── ...
```

The most relevant folders in the `build` for configuration is `build/conf/local.conf`. This includes many parameters for how the OS should be built.

The `build/output` folder might be relevant since it is generated by `gen-machineconf` in `generate_device_tree.sh` before it creates the final device trees.

The final output image is found in `build/tmp/deploy/images/<MACHINE>`. The relevant OS files are shown in the directory illustration above.

## Folder 4: `output`

Finally, we have `xilinx_bitbake/output` folder, created by `copy_ouput.sh`:

```
output
└── <MACHINE>
│   └── core-image-gfex-<MACHINE>.wic
│   └── BOOT
│   │   └── boot.bin
│   │   └── boot.scr
│   │   └── Image
│   │   └── system.dtb
│   │   └── u-boot.bin
│   └── ROOT
│   │   └── core-image-gfex-<MACHINE>.rootfs.ext4
```
